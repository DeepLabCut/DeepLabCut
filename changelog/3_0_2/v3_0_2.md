# DeepLabCut 3.0.2

DeepLabCut 3.0.2 is a patch release that hardens everyday PyTorch workflows,
improves config and export reliability, prepares the dependency stack for newer
NumPy / pandas / Matplotlib, and adds a machine-readable docs/API index for
agent-assisted development.

This release promotes the current `dev` snapshot to `main`.

**Compare:** https://github.com/DeepLabCut/DeepLabCut/compare/v3.0.1...v3.0.2
*(adjust tags to match the previous release / this tag)*

## Highlights

- More reliable COCO training: `model_cfg.metadata` is authoritative, with
  fail-fast validation against annotation JSON (#3435).
- Safer legacy project configs: empty / `null` top-level YAML fields are treated
  as unset; `ignore_empty` is removed (#3439).
- Normalized `export_model` pickles for downstream / real-time consumers (#3473).
- Detector `null` thresholds resolve to field defaults instead of crashing
  (#3470, #3475).
- PyTorch `analyze_videos` no longer crashes on clips with zero detections;
  empty predictions skip DataFrame export with a clear warning (#3488).
- Public LLM-friendly knowledge index (`llms.txt`, `docs.jsonl`, `api.jsonl`)
  plus hardening follow-up and `AGENTS.md` (#3453, #3494, #3483).
- Forward-compatibility work for NumPy 2, pandas 3 CoW, and Matplotlib 3.9
  (#3420, #3445, #3394).

## Agentic interaction

Coding agents and LLM tools can now discover DeepLabCut knowledge without
scraping HTML.

CI builds and deploys a structured index with the docs site:

- `llms.txt` — [llmstxt.org](https://llmstxt.org)-style entry point at the docs
  root ([published here](https://deeplabcut.github.io/DeepLabCut/llms.txt)
  after deploy)
- `knowledge/manifest.json` — which API versions are indexed and which is current
- `knowledge/main/docs.jsonl` — one JSON object per user-docs page and heading
- `knowledge/<version>/api.jsonl` — one JSON object per documented API symbol

Records use stable ids (`docs:…`, `api:…`) and absolute URLs so agents can scan
lazily. User-docs rows live under `main`; released API labels get their own
`api.jsonl`.

`llms.txt` points at both the latest stable API reference (release alias) and
the rolling `main` developer docs, so agents can choose pinned vs tip signatures
(#3494).

Also added: repository-root
[`AGENTS.md`](https://github.com/DeepLabCut/DeepLabCut/blob/main/AGENTS.md),
shared guidance for humans and coding agents (PyTorch-first, optional
dependencies, data safety, public API stability, and pointing at the published
index).

## Behavioral notes

### COCOLoader (#3435)

`bodyparts` / individuals capacity now come from `model_cfg.metadata`, matching
`DLCLoader`. Construction validates `train.json` and `test.json` and raises
`ValueError` if an image exceeds configured capacity or bodyparts do not match.
Projects that previously relied on capacity inferred only from the busiest
training image should set `max_individuals` (and bodyparts) explicitly.

### ProjectConfig empty / null fields (#3439)

Empty top-level YAML fields are treated as unset and emit an actionable warning.
`DLCBaseConfig.from_yaml(..., ignore_empty=...)` no longer accepts `ignore_empty`
(breaking for that optional parameter). Lower-level `read_config(..., ignore_empty=...)`
deprecates the argument.

### Exported models (#3473)

`export_model` now calls `PoseConfig.to_dict(normalize=True)`, so pickles store
primitives (`Path` → `str`, enums → `str`, etc.). Prefer re-exporting models for
consumers that load the pickled config.

### Detector score threshold (#3470, #3475)

`box_score_thresh: null` maps to the field default via `DefaultIfNone` instead of
failing at Faster R-CNN inference. This is the first user of a reusable
null→default validator for typed configs.

### Empty video predictions (#3488)

PyTorch `analyze_videos` can legitimately return no predictions (e.g. top-down
with no detections for the whole clip). That path no longer hits
`OverflowError` / `np.stack([])`. No prediction DataFrame is written for an
all-empty clip; a clear warning is emitted instead. Related: #3485.

### NumPy tracklet ranking (#3420)

Tracklet rank estimation uses a dense SVD instead of
`scipy.linalg.interpolative.svd`. The result is exact and deterministic where the
previous path was randomized. The `numpy<2` upper bound is unchanged in this
release.
